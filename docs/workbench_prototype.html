1. Tokio 异步运行时无界 Channel 导致内存泄漏排查与避坑

今日讨论焦点源于群友反馈：线上高并发长连接网关在连续运行 72 小时后发生 OOM，内存从平稳期的 120MB 一路膨胀至 2.4GB，但 CPU 负载始终保持在 15% 以下。

排查过程与根因：多位资深群友协同使用 tokio-console 对线上 Task 进行快照采样，最终定位到内部日志与遥测打点模块采用了 tokio::sync::mpsc::unbounded_channel()。在下游出现突发延迟时，由于缺乏 Backpressure（背压保护），生产端无节制推入，导致堆积的未处理 Future 积压超过 40 万个。

最终解决方案：全面废弃 unbounded channel，改用固定容量 channel(2048)，并在发送失败或满载时触发显式采样降级。修复后内存占用已回落至 135MB 并持续平稳。

2. Rust 官方发布 v1.82.0 稳定版讨论热点

官方稳定版更新引发广泛探讨。大家最关注的新增特性是 addr_of! / addr_of_mut! 对裸指针解引用的严格校验机制，以及在 FFI 与嵌入式领域无需通过引用即可创建指针的巨大安全性优势。

群友分享了老代码升级后遇到的部分由于内联展开引起的编译期 warning 修复方案，普遍认为该版本为近年裸指针安全性最扎实的提升之一。
