# 核心技术议题 · 01 事故复盘与避坑

Tokio 异步运行时因无界 Channel 导致线上网关内存泄漏事故复盘

今日讨论最热烈的生产事故复盘：某群友团队的高并发网关服务在连续运行 72 小时后发生 OOM 崩溃，内存占用从平稳期的 120MB 一路飙升至 2.4GB，但 CPU 使用率始终低于 15%，且无任何 panic 异常日志。

排查过程：群内多位开发者协助使用 tokio-console 进行 Task 快照采样，发现内部打点上报模块采用了 unbounded_channel()。
事故根因：在网络短时抖动时缺乏背压（Backpressure）机制，生产端持续推入，导致堆积了超 40 万个未释放的异步 Task。
解决方案：全面切换为有界 channel(2048) 并增加超时丢弃降级，修复后内存平稳保持在 130MB。

官方 v1.82 版本的更新引发了热烈探讨。大家最认可的新特性是 addr_of! / addr_of_mut! 对裸指针解引用的严格校验机制，以及在无需借用开销下安全操作未对齐内存的收益。
