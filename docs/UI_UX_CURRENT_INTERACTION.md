# TGTLDR 当前 UI/UX 交互逻辑总结

> 基于当前前端代码与页面结构整理。  
> 更新时间：2026-11-02

## 一、整体交互模型

TGTLDR 当前是一个偏桌面端的“编辑风格管理后台”：

- 以三个一级页面为主：群组、摘要、系统配置
- 列表负责管理和筛选
- 右侧抽屉负责阅读摘要与历史记录
- 模态弹窗负责一次性任务和确认流程
- 页面之间重新挂载并重新请求数据，不是常驻三栏工作台

```text
/
├─ 未设置密码 → /setup
├─ 已设置密码但未登录 → /login
├─ 已登录但配置或 Telegram 未完成 → /setup
└─ 已完成 → /dashboard → /dashboard/chats

后台
├─ 群组
│  └─ 单群聊天记录
│     └─ 当天摘要抽屉
├─ 摘要
│  ├─ 每日总览
│  ├─ 快速回顾
│  └─ 摘要详情抽屉
└─ 系统配置
   ├─ Telegram
   ├─ 摘要引擎
   ├─ 偏好设置
   ├─ 安全
   └─ Bot 推送
```

首页本身没有业务内容，只负责读取 `bootstrap` 状态后做路由分流。

## 二、入口、登录与首次设置

### 1. 首页分流

`/` 会调用 `/api/bootstrap`，并按以下顺序跳转：

1. 没有访问密码 → `/setup`
2. 有密码但未登录 → `/login`
3. 已登录，但基础配置或 Telegram 未完成 → `/setup`
4. 全部完成 → `/dashboard`，随后进入 `/dashboard/chats`

当前实现中，如果 `bootstrap` 请求失败，会直接跳到 `/setup`。这会让后端或数据库故障看起来像“配置丢失”。

### 2. 登录页

登录页只支持访问密码登录：

- 输入访问密码
- 回车或点击“登录”提交
- 登录成功后重新读取 `bootstrap`
- 配置完整则进入群组页，否则进入首次设置

当前没有找回密码、多用户、第三方登录或会话管理界面。

### 3. 首次设置向导

首次设置分为四步：

1. **访问密码**
2. **基础配置**
3. **Telegram 登录**
4. **Bot 推送**

步骤条会显示当前进度，并允许跳转到已经解锁的步骤。

#### 第 1 步：访问密码

- 输入密码
- 再次确认密码
- 密码至少 8 位
- 设置成功后进入基础配置

#### 第 2 步：基础配置

包含：

- Telegram API ID
- Telegram API Hash
- OpenAI Base URL
- OpenAI API Key
- 模型
- Temperature
- 输出长度自动/自定义
- 上下文窗口自动/自定义
- 流式/非流式
- 默认时区
- 界面语言
- 测试 OpenAI 连接

#### 第 3 步：Telegram 登录

交互链路：

```text
手机号 → 验证码 → 两步验证（如有）→ 同步群组
```

支持：

- 国家码和手机号
- 发送验证码
- 重新发送验证码
- 返回修改手机号
- 输入两步验证密码
- 登录后重试群组同步

#### 第 4 步：Bot 推送

- Bot 推送可以保持关闭
- 开启时需要 Bot Token
- 可以自动获取目标 Chat ID
- 存在多个候选会话时手动选择
- 完成后保存并进入后台

## 三、全局导航与页面框架

### 桌面端

左侧为浮动侧边栏：

- 品牌和产品说明
- 群组
- 摘要
- 系统配置
- Telegram 连接状态
- Bot 推送状态

### 中等屏幕

`≤1100px` 时：

- 左侧侧边栏变为底部固定 Tab Bar
- 品牌和侧边栏状态隐藏
- 系统配置页单独显示移动端连接状态卡

### 移动端

`≤640px` 时：

- 群组表格变为卡片列表
- 摘要筛选折叠为“筛选”按钮
- 统计卡变成横向紧凑条
- 右侧抽屉变为全屏底部面板
- 模态弹窗变为底部 Sheet
- 保存栏按钮变为全宽

## 四、群组页交互

群组页是当前最“管理后台化”的页面。

### 页面结构

顶部三张统计卡：

- 已同步群组
- 已启用消息保存
- 已启用 AI 总结

下方为群组表格。

### 筛选

支持：

- 群名搜索
- 群类型
- 消息保存状态
- AI 总结状态

筛选全部在浏览器本地完成，不写入 URL，刷新页面后筛选条件会丢失。

### 群组行操作

点击群名进入该群聊天记录页。

右侧操作包括：

- **刷新话题**：仅论坛超级群显示
- **编辑配置**：在表格下方展开编辑区
- **加载历史消息**：在表格下方展开历史回补面板

### 群组编辑

编辑区不是独立页面或抽屉，而是插入表格中的展开行。

配置项包括：

- 使用哪个 Telegram 账号采集
- 消息保存开关
- AI 总结开关
- Telegram 推送方式
- 摘要时间
- 模型 override
- 是否保留机器人消息
- 过滤发言人
- 过滤关键词
- 群聊背景
- 摘要额外要求

保存时会一次性提交整个群组配置。

### 论坛超级群与子话题

论坛超级群名称前有展开按钮。展开后以缩进子行显示话题：

- 话题标题
- Telegram topic ID
- 已关闭/已失效状态
- 消息保存开关
- AI 总结开关
- 模型是否继承自群组

当前话题只支持存储和摘要开关，没有话题级别的完整配置，例如：

- 独立摘要时间
- 独立 Prompt
- 独立过滤规则
- 独立模型设置

聊天记录页也还没有话题筛选入口，仍以整个群为浏览单位。

### 全局消息搜索

群组页右上角搜索按钮可以展开跨群消息搜索：

- 搜索所有群组内的消息、发言人或 `@username`
- 搜索结果分页
- 点击结果跳转到对应群的聊天记录，并定位到具体消息

### 历史消息回补

历史回补面板支持：

- 最近 1 天
- 最近 3 天
- 最近 7 天
- 最近 30 天
- 自定义日期范围

提交后会创建后台任务，并通过持久 Toast 显示进度。任务完成后会刷新群组列表。

## 五、摘要页交互

摘要页是当前信息消费的核心。

### 顶部任务入口

#### 每日总览

- 未启用时点击会弹出确认框
- Bot 未配置时引导跳转到系统配置的 Bot 页
- 已启用时打开每日总览历史抽屉
- 显示最近一次总览日期
- 历史抽屉支持查看正文、来源摘要、重新生成和重新发送

#### 快速回顾

- 从已有每日摘要中生成阶段回顾
- 点击后打开两步向导
- 时间周期支持 7/14/30 天和自定义范围，最多 90 天
- 固定周期截止到昨天
- 第二步选择参与群组
- 支持全选和清空
- 可选是否发送到 Telegram
- 生成时弹窗内轮询
- 关闭弹窗后任务继续在后台执行

### 摘要统计卡

四张卡都可以点击筛选：

- 摘要记录
- 生成成功
- 处理中
- 生成失败

点击后会重置其他筛选条件，并滚动到摘要列表。

失败卡内还包含“一键重跑全部失败任务”的恢复入口，可查看重跑进度和失败详情。

### 摘要列表

支持：

- 摘要关键词搜索
- 群组筛选
- 论坛群的话题筛选
- 生成状态筛选
- Bot 发送状态筛选
- 开始日期和结束日期
- 手动补跑
- 分页，每页 20 条

手动补跑只显示已启用 AI 总结的群组；论坛群可以进一步选择具体话题。

摘要记录以列表行呈现，点击后从右侧打开详情抽屉。

### 摘要详情抽屉

展示：

- 生成状态
- 发送状态
- 模型、消息数、分块数
- 查看原始 Prompt
- 重新生成
- 通过 Bot 发送
- Markdown 正文

失败摘要会显示：

- 错误信息
- 自动重试次数
- 下次重试时间
- OpenAI 请求参数
- System Prompt
- User Prompt
- 复制错误上下文

原始 Prompt 会再叠一层抽屉，展示：

- 系统提示词
- 各个消息分块
- 最终合并提示词

当前摘要详情没有：

- 一键复制整篇摘要
- 导出 Markdown
- 直接跳转到对应日期的原始聊天记录
- 目录导航
- 全屏阅读模式

## 六、聊天记录页交互

聊天记录页是当前少数使用 URL 参数驱动交互的页面。

URL 参数包括：

- `date`：当前日期
- `q`：搜索关键词
- `searchPage`：搜索分页
- `messageId`：定位到的具体消息
- `filters`：是否应用群组过滤规则
- `summaryDate`：是否打开当天摘要抽屉

因此支持浏览器前进/后退和搜索结果深链接。

### 日期浏览

- 默认打开最近有消息的日期
- 上一有消息日 / 下一有消息日
- 日历选择器
- 日历标记有消息的日期
- 最近 30 天活动条
- 点击活动条日期切换记录

### 消息浏览

- 初始加载最多 2000 条
- 向上滚动或点击按钮加载更早的 500 条
- 加载更早消息时保持滚动位置
- 搜索结果点击后跳转到对应日期，并居中高亮具体消息
- 可返回搜索结果
- 可回到当天最新消息

### 消息内容

支持：

- 发言人、头像、用户名、Bot 标记、时间
- 回复预览
- 图片、视频、音频、文件、贴纸
- 手动下载
- 下载失败重试
- 超限文件确认下载
- TGS 动画贴纸

### 当天摘要

聊天记录页可以打开当天摘要抽屉。

如果当天没有摘要，只显示空状态，并提示前往摘要页手动生成。

## 七、系统配置页交互

系统配置页分为五个横向标签：

- Telegram
- 摘要引擎
- 偏好设置
- 安全
- Bot 推送

标签状态写入 URL 的 `?tab=`，因此可以直接链接到某个设置分类。

### Telegram

- 配置 API ID / API Hash
- 查看多个 Telegram 账号
- 同步群组
- 重新登录失效账号
- 手机号 → 验证码 → 两步验证
- 删除账号
- 若账号仍被群组使用，删除按钮禁用并显示原因

### 摘要引擎

- Base URL
- Model
- API Key
- Temperature
- 输出长度自动/自定义
- 上下文窗口自动/自定义
- 流式/非流式
- 并发摘要数
- 重试次数
- 测试连接

测试连接目前只通过 Toast 提示成功或失败，没有延迟、请求详情或错误响应回显。

### 偏好设置

- 默认时区
- 中文/英文
- 是否自动下载消息附件

### 安全

- 修改访问密码
- 退出登录

### Bot 推送

- 开启/关闭 Bot
- 按群分别发送
- 每日总览合并发送
- Bot Token
- 自动获取目标 Chat ID
- 多个候选会话时手动选择

除安全页外，页面底部有固定保存栏。

但“获取 Chat ID”会自动单独保存，与页面统一保存形成双轨：页面上的其他未保存修改不会被这次自动保存一并提交。

## 八、跨页面交互机制

### 1. 页面切换是重新挂载

三个一级页面各自维护本地状态，没有全局查询缓存。

切换页面后通常会重新请求：

- 群组列表
- 系统设置
- 摘要统计
- Bootstrap 状态

页面切换不是常驻三栏工作台式的内容替换，而是重新挂载和重新取数。

### 2. 异步任务反馈分散

不同任务使用不同反馈方式：

- 历史回补：持久 Toast + 3 秒轮询
- 摘要处理中：摘要页 3 秒轮询
- 每日总览/快速回顾：抽屉内轮询
- 失败任务恢复：5 秒轮询 + 恢复详情弹层
- Bot 发送：Toast + 列表刷新

目前没有统一的“任务中心”或全局后台任务面板。

### 3. 抽屉与弹窗

- 摘要阅读、每日总览、快速回顾历史、原始 Prompt 都使用右侧抽屉
- 快速回顾创建、每日总览启用、Bot 引导使用模态弹窗
- 抽屉支持 Escape、点击遮罩关闭和锁定页面滚动
- 移动端抽屉变成底部全屏面板
- 移动端弹窗变成底部 Sheet

### 4. 全局反馈

页面操作主要通过 Toast 提示结果：

- 成功提示 3.2 秒后自动消失
- 历史回补等后台任务使用持久 Toast
- 部分后台任务完成后通过自定义事件刷新 Bootstrap 状态和列表

## 九、当前交互逻辑的主要特征与缺口

### 已经比较清晰的交互

- 首次设置、登录、后台三段式入口明确
- 群组级编辑、话题级快捷开关已经形成基本层级
- 摘要搜索、状态筛选、手动补跑、失败恢复比较完整
- 快速回顾和每日总览的历史、来源、重试链路已打通
- 聊天记录页的日期、搜索、消息定位和深链接设计较成熟
- 移动端不是简单缩放，而是有表格卡片化和底部导航适配

### 仍然明显的交互断层

1. 群组页是表格内联编辑，摘要页是右侧抽屉阅读，两者交互模型不统一。
2. 话题能力只覆盖一部分：群组页能展开话题、摘要页能筛选话题，但聊天记录页没有话题入口。
3. 摘要和原始消息没有形成双向证据链：从摘要详情不能直接跳到当天原消息。
4. 筛选状态不统一：群组筛选和摘要筛选不写入 URL，聊天记录筛选写入 URL。
5. 统计卡行为不一致：摘要页统计卡可筛选，群组页统计卡只是展示。
6. 首次设置与系统设置大量重复：两套表单、两套 Telegram 登录、两套 Bot 配置逻辑。
7. 没有批量群组操作：大量群组时只能逐行编辑。
8. 没有统一任务中心：回补、摘要、总览、快速回顾、Bot 投递的进度分散在不同组件。
9. 摘要详情缺少高频消费动作：复制、导出、跳原消息、全屏阅读。
10. 页面切换依赖重新请求，缺少跨页面状态缓存和常驻工作区。

---

## 十、一句话总结

当前产品已经具备“群组配置 → 消息采集 → 摘要生成 → 总览/快速回顾 → Bot 投递”的完整业务闭环，但 UI 仍以传统 CRUD 后台为主，信息消费层是右侧抽屉，尚未形成围绕“群组层级、摘要阅读、原消息证据”三者联动的统一工作台。
